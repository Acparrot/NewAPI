# New API 后续使用、维护、运营基础知识

本文面向当前部署环境：腾讯云轻量应用服务器、Ubuntu 22.04、Docker Compose、New API + PostgreSQL + Redis + Caddy，访问域名为 `https://api.jiatuc.cn`。

## 1. 你现在拥有的系统

New API 是一个大模型 API 网关和管理后台。它本身不提供模型算力，而是把你合法获得的上游 API Key 接入进来，再统一管理用户、令牌、渠道、额度、日志和模型路由。

当前服务器上主要有 4 个容器：

```text
new-api          New API 主程序
postgres         数据库，保存用户、渠道、令牌、日志等核心数据
redis            缓存和部分运行状态
new-api-caddy    HTTPS 入口，负责 api.jiatuc.cn 的证书和反向代理
```

服务器防火墙只应开放：

```text
22    SSH 登录
80    HTTP，给 Caddy 申请证书和跳转
443   HTTPS，正式访问入口
```

不要开放：

```text
3000  New API 内部端口
5432  PostgreSQL
6379  Redis
```

## 2. 第一次登录后应该做什么

初始化完成后，建议按这个顺序配置：

1. 创建管理员账号，并保存好密码。
2. 进入后台设置，先关闭或限制公开注册。
3. 添加第一个上游渠道，例如 OpenAI、Azure、DeepSeek、Claude、Gemini 或其他兼容渠道。
4. 添加一个测试令牌，只给自己使用。
5. 用令牌发起一次简单 API 请求，确认模型调用链路正常。
6. 再考虑是否开放给其他用户使用。

不要一开始就打开支付、充值、公开注册、邀请注册、兑换码等运营功能。先保证自己能稳定调用，再逐步开放。

## 3. 常用后台概念

### 渠道

渠道就是上游 API 服务。一个渠道通常包含：

```text
上游平台类型
API Key
模型列表
基础地址
权重和优先级
分组
状态检测
```

建议先少量添加渠道，确认稳定后再增加复杂路由。

### 模型

模型是用户实际调用时使用的名称。New API 可以做兼容和转发，但你要确保：

```text
模型名称写对
上游支持这个模型
价格倍率配置合理
分组权限没有误放开
```

### 令牌

令牌是给客户端调用 API 的凭证。建议：

```text
不同用途使用不同令牌
给每个令牌设置额度或过期时间
令牌泄露后立即禁用或删除
不要把管理员账号密码给客户端使用
```

### 用户和额度

如果只是自用，可以只保留管理员和少量内部用户。如果要运营给别人用，需要认真考虑：

```text
实名、合规、日志留存
额度充值和退款
滥用和风控
上游 API 的服务条款
成本核算
```

## 4. 日常维护命令

在腾讯云终端登录服务器后执行：

```bash
cd /opt/new-api
sudo docker compose ps
```

查看服务状态。

```bash
cd /opt/new-api
sudo docker compose logs --tail=100 new-api
```

查看 New API 最近日志。

```bash
cd /opt/new-api
sudo docker compose logs --tail=100 caddy
```

查看 HTTPS 和证书日志。

```bash
curl -i http://127.0.0.1:3000/api/status
```

在服务器内部检查 New API 是否健康。

## 5. 更新 New API

更新前先备份数据库，见下一节。确认备份完成后执行：

```bash
cd /opt/new-api
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 new-api
```

如果更新后异常，可以先查看日志，不要立刻删除容器或卷。

## 6. 备份与恢复

PostgreSQL 是最重要的数据。建议每次升级前备份一次，日常至少每周备份一次。

创建备份目录：

```bash
sudo mkdir -p /opt/new-api/backups
sudo chown -R "$USER":"$USER" /opt/new-api/backups
```

备份数据库：

```bash
cd /opt/new-api
sudo docker compose exec -T postgres pg_dump -U newapi -d new-api > backups/new-api-$(date +%F-%H%M%S).sql
```

查看备份文件：

```bash
ls -lh /opt/new-api/backups
```

恢复数据库是高风险操作，恢复前必须先停止服务并确认备份文件正确。等真正需要恢复时，再单独制定步骤。

## 7. 安全运营建议

基础建议：

```text
管理员密码使用强密码
不要公开管理员账号
不要把上游 API Key 发给任何人
不要开放数据库和 Redis 公网端口
定期备份
定期更新镜像
发现异常消耗时先禁用对应令牌或渠道
```

如果要对外运营，还需要额外考虑：

```text
ICP备案和服务合规
上游 API 授权和转售条款
用户协议和隐私政策
内容安全和滥用处理
日志留存
支付和退款规则
成本核算
```

## 8. 常见故障判断

### 域名打不开

先看 DNS：

```bash
nslookup api.jiatuc.cn
```

再看腾讯云防火墙是否开放 `80` 和 `443`。

### HTTPS 证书失败

查看 Caddy 日志：

```bash
cd /opt/new-api
sudo docker compose logs --tail=100 caddy
```

如果日志出现 timeout，通常是 `80/443` 没开放或域名没有解析到服务器。

### 后台 502

看 New API 是否运行：

```bash
cd /opt/new-api
sudo docker compose ps
sudo docker compose logs --tail=100 new-api
```

### 模型调用失败

按顺序检查：

```text
上游 API Key 是否有效
渠道模型名称是否正确
渠道分组是否匹配令牌分组
余额或额度是否充足
上游服务是否限流或不可用
New API 错误日志里显示什么
```

## 9. 建议的日常节奏

每周：

```text
检查 docker compose ps
备份数据库
查看异常日志
查看上游渠道消耗
```

每月：

```text
更新镜像
检查服务器磁盘
检查腾讯云安全组/防火墙
整理无用令牌和用户
```

重要变更前：

```text
先备份
再更新
更新后验证登录、渠道、令牌、模型调用
```
