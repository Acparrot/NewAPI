# New API 部署复盘

本文记录本次从购买服务器和域名到完成 New API 部署的过程。文档会保留关键技术决策和排错思路，但不记录任何密码、API Key、数据库密钥或会话密钥。

## 1. 初始目标

目标是部署一个 New API 大模型 API 中转站，并通过独立域名访问。

最终结果：

```text
访问域名：https://api.jiatuc.cn
服务器：腾讯云轻量应用服务器
系统：Ubuntu 22.04 LTS
部署方式：Docker Compose
服务组成：New API + PostgreSQL + Redis + Caddy
```

## 2. 前期判断

一开始先确认 New API 官方推荐的部署方式。项目文档显示：

```text
推荐使用 Docker Compose
支持 SQLite、MySQL、PostgreSQL
生产环境可使用 PostgreSQL 或 MySQL
Redis 可用于缓存
多机或 Redis 场景需要设置 SESSION_SECRET 和 CRYPTO_SECRET
```

基于长期维护和安全考虑，本次没有选择单容器 SQLite，而是选择：

```text
PostgreSQL 作为主数据库
Redis 作为缓存
Caddy 负责 HTTPS 和反向代理
Docker Compose 统一管理服务
```

## 3. 域名决策

用户注册了主域名 `jiatuc.cn`。讨论后决定使用：

```text
api.jiatuc.cn
```

原因：

```text
API 服务使用 api 子域名更清晰
根域名 jiatuc.cn 可以保留给官网、备案页或说明页
后续迁移或扩展时更容易管理
```

DNS 解析添加为：

```text
主机记录：api
记录类型：A
记录值：服务器公网 IPv4
```

后续确认 `api.jiatuc.cn` 已正确解析到服务器。

## 4. 服务器体检

在腾讯云网页终端登录服务器后，先执行只读检查，确认环境：

```text
系统：Ubuntu 22.04 LTS
内核：Linux 5.15
内存：约 3.3 GiB
磁盘：约 40 GiB
Docker：已安装
Docker Compose：已安装
Git：已安装
```

这说明服务器满足小规模 New API 部署条件。

## 5. 部署方案变化

初版方案是主机安装 Caddy，再通过 Caddy 反代到本机 `127.0.0.1:3000`。

执行前进一步简化为：

```text
将 Caddy 也放进 Docker Compose
Compose 同时管理 new-api、postgres、redis、caddy
只开放 80/443 给 Caddy
New API 的 3000 只绑定本机
PostgreSQL 和 Redis 不暴露公网
```

这个方案更便于后续维护：

```text
启动：docker compose up -d
查看：docker compose ps
日志：docker compose logs
更新：docker compose pull && docker compose up -d
```

## 6. 部署中遇到的问题

### 问题 1：本地无法直接接管浏览器或电脑

尝试使用 Computer Use 和 Browser 插件操作腾讯云控制台时，Windows 辅助进程报错：

```text
CreateProcessAsUserW failed: 5
```

处理方式：

```text
不强行绕过
改为用户在腾讯云网页终端粘贴命令
助手根据截图和输出继续判断
```

这个方式虽然手动一些，但更稳，也避免了在网页里误操作。

### 问题 2：Docker 权限不足

第一次执行安装脚本时，出现 Docker socket 权限错误：

```text
permission denied while trying to connect to the Docker daemon socket
```

原因是当前 `ubuntu` 用户没有直接访问 Docker 的权限。

解决方式：

```bash
sudo bash install-new-api.sh
```

使用 sudo 执行后，镜像拉取和容器启动成功。

### 问题 3：服务启动后公网打不开

容器启动后，页面访问 `https://api.jiatuc.cn` 超时。

服务器日志中可以看到：

```text
Caddy 正在监听 80/443
New API 正常返回状态
证书流程曾出现外部连接 timeout
```

本地测试也显示：

```text
DNS 正确
80 端口公网不通
443 端口公网不通
```

判断是腾讯云轻量服务器防火墙未开放 `80/443`。

解决方式：

```text
在腾讯云轻量应用服务器防火墙中开放 TCP 80
在腾讯云轻量应用服务器防火墙中开放 TCP 443
不要开放 3000、5432、6379
```

开放后，`https://api.jiatuc.cn` 可以访问。

最终访问 New API 页面成功，并进入系统初始化界面。

初始化页显示数据库为 PostgreSQL，说明：

```text
New API 已连接 PostgreSQL
Caddy HTTPS 反向代理工作正常
域名解析和公网防火墙已打通
Docker Compose 栈运行成功
```

## 8. 关键经验

本次部署的核心经验：

```text
先做 DNS，再做 HTTPS
先做服务器体检，再安装服务
容器启动成功不等于公网能访问
公网打不开时优先查防火墙和端口
不要把数据库、Redis、New API 内部端口暴露到公网
所有密码和密钥都用随机值生成，不写默认 123456
```
