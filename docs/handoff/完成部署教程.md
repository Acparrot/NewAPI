# New API 从零部署教程

本文是一份文字版完整流程，适合复现本次部署。示例使用腾讯云轻量应用服务器、Ubuntu 22.04、Docker Compose、域名 `api.jiatuc.cn`。

如果要给别人参考，请把域名和 IP 替换成自己的。

## 1. 准备资源

需要准备：

```text
一台云服务器
一个域名
服务器 SSH 或网页终端登录权限
```

推荐服务器最低配置：

```text
系统：Ubuntu 22.04 LTS
内存：2 GiB 以上
磁盘：30 GiB 以上
```

本次使用：

```text
云厂商：腾讯云轻量应用服务器
系统：Ubuntu 22.04 LTS
访问域名：api.jiatuc.cn
```

## 2. 解析域名

在腾讯云 DNSPod 或云解析里添加记录：

```text
记录类型：A
主机记录：api
记录值：服务器公网 IPv4
TTL：默认或 600
```

完成后检查：

```bash
nslookup api.jiatuc.cn
```

或者在 Windows PowerShell 中：

```powershell
Resolve-DnsName api.jiatuc.cn -Type A -Server 223.5.5.5
```

确认返回的是服务器公网 IP。

## 3. 登录服务器并体检

登录服务器后执行：

```bash
whoami
uname -a
cat /etc/os-release
pwd
df -h /
free -h
command -v docker && docker --version || echo "docker not installed"
docker compose version || echo "docker compose not installed"
command -v git && git --version || echo "git not installed"
```

确认：

```text
系统是 Ubuntu/Debian
Docker 已安装
Docker Compose v2 可用
磁盘和内存足够
```

如果 Docker 不存在，需要先安装 Docker；本次服务器已经预装 Docker，因此跳过安装。

## 4. 开放腾讯云防火墙

在腾讯云轻量应用服务器控制台打开实例的防火墙页面，确保入站规则包含：

```text
TCP 22    SSH
TCP 80    HTTP
TCP 443   HTTPS
```

不要开放：

```text
TCP 3000
TCP 5432
TCP 6379
```

这些端口只在服务器内部或 Docker 网络内部使用。

## 5. 创建安装脚本

在服务器终端执行：

```bash
nano install-new-api.sh
```

粘贴以下脚本。注意把 `DOMAIN` 改成自己的域名：

```bash
#!/usr/bin/env bash
set -euo pipefail

DOMAIN="api.jiatuc.cn"
APP_DIR="/opt/new-api"

if ! command -v docker >/dev/null 2>&1; then
  echo "Docker is not installed. Install Docker first, then rerun this script." >&2
  exit 1
fi

if ! docker compose version >/dev/null 2>&1; then
  echo "Docker Compose v2 is not available. Install Docker Compose first, then rerun this script." >&2
  exit 1
fi

sudo mkdir -p "${APP_DIR}"
sudo chown -R "${USER}:${USER}" "${APP_DIR}"
cd "${APP_DIR}"

POSTGRES_PASSWORD="$(openssl rand -hex 32)"
REDIS_PASSWORD="$(openssl rand -hex 32)"
SESSION_SECRET="$(openssl rand -hex 32)"
CRYPTO_SECRET="$(openssl rand -hex 32)"

cat > .env <<EOF
TZ=Asia/Shanghai
NEW_API_PORT=127.0.0.1:3000
FRONTEND_BASE_URL=https://${DOMAIN}
NEW_API_DOMAIN=${DOMAIN}

POSTGRES_USER=newapi
POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
POSTGRES_DB=new-api

REDIS_PASSWORD=${REDIS_PASSWORD}

SESSION_SECRET=${SESSION_SECRET}
CRYPTO_SECRET=${CRYPTO_SECRET}

ERROR_LOG_ENABLED=true
BATCH_UPDATE_ENABLED=true
NODE_NAME=new-api-node-1
STREAMING_TIMEOUT=300
RELAY_IDLE_CONN_TIMEOUT=90
EOF

cat > Caddyfile <<EOF
${DOMAIN} {
	encode gzip
	reverse_proxy new-api:3000
}
EOF

cat > docker-compose.yml <<'EOF'
services:
  new-api:
    image: calciumion/new-api:latest
    container_name: new-api
    restart: always
    command: --log-dir /app/logs
    ports:
      - "${NEW_API_PORT:-127.0.0.1:3000}:3000"
    volumes:
      - ./data:/data
      - ./logs:/app/logs
    environment:
      SQL_DSN: "postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}"
      REDIS_CONN_STRING: "redis://:${REDIS_PASSWORD}@redis:6379"
      TZ: "${TZ:-Asia/Shanghai}"
      FRONTEND_BASE_URL: "${FRONTEND_BASE_URL}"
      SESSION_SECRET: "${SESSION_SECRET}"
      CRYPTO_SECRET: "${CRYPTO_SECRET}"
      ERROR_LOG_ENABLED: "${ERROR_LOG_ENABLED:-true}"
      BATCH_UPDATE_ENABLED: "${BATCH_UPDATE_ENABLED:-true}"
      NODE_NAME: "${NODE_NAME:-new-api-node-1}"
      STREAMING_TIMEOUT: "${STREAMING_TIMEOUT:-300}"
      RELAY_IDLE_CONN_TIMEOUT: "${RELAY_IDLE_CONN_TIMEOUT:-90}"
    depends_on:
      redis:
        condition: service_started
      postgres:
        condition: service_healthy
    networks:
      - new-api-network
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O - http://localhost:3000/api/status | grep -Eq '\"success\"[[:space:]]*:[[:space:]]*true' || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 3

  caddy:
    image: caddy:2-alpine
    container_name: new-api-caddy
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      new-api:
        condition: service_started
    networks:
      - new-api-network

  redis:
    image: redis:7-alpine
    container_name: redis
    restart: always
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}"]
    volumes:
      - redis_data:/data
    networks:
      - new-api-network

  postgres:
    image: postgres:15
    container_name: postgres
    restart: always
    environment:
      POSTGRES_USER: "${POSTGRES_USER}"
      POSTGRES_PASSWORD: "${POSTGRES_PASSWORD}"
      POSTGRES_DB: "${POSTGRES_DB}"
    volumes:
      - pg_data:/var/lib/postgresql/data
    networks:
      - new-api-network
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  pg_data:
  redis_data:
  caddy_data:
  caddy_config:

networks:
  new-api-network:
    driver: bridge
EOF

echo "Pulling images..."
docker compose pull

echo "Starting New API stack..."
docker compose up -d

echo "Waiting for services..."
sleep 10

docker compose ps

echo "New API recent logs:"
docker compose logs --tail=80 new-api

echo "Local health check:"
curl -fsS http://127.0.0.1:3000/api/status || true
echo

echo "Listening ports:"
sudo ss -lntp | grep -E ':(22|80|443|3000|5432|6379)\b' || true

echo "Done. Test: https://${DOMAIN}"
```

保存：

```text
Ctrl+O
回车
Ctrl+X
```

## 6. 执行安装

如果当前用户没有 Docker 权限，直接用 sudo 执行：

```bash
sudo bash install-new-api.sh
```

等待镜像拉取和容器启动完成。

成功时会看到类似：

```text
Container redis Started
Container postgres Healthy
Container new-api Started
Container new-api-caddy Started
```

## 7. 验证服务

执行：

```bash
cd /opt/new-api
sudo docker compose ps
curl -i http://127.0.0.1:3000/api/status
sudo docker compose logs --tail=80 caddy
sudo ss -lntp | grep -E ':(22|80|443|3000|5432|6379)\b' || true
```

确认：

```text
new-api 运行
postgres healthy
redis 运行
caddy 运行
127.0.0.1:3000 有响应
0.0.0.0:80 和 0.0.0.0:443 已监听
```

然后浏览器访问：

```text
https://api.jiatuc.cn
```

如果看到 New API 初始化页面，说明部署成功。

## 8. 初始化 New API

进入页面后按提示完成：

```text
数据库检查
创建管理员账号
选择使用模式
完成初始化
```

使用模式后续可以在后台调整。建议第一次选择保守的自用或内部使用模式。

## 9. 如果打不开怎么排查

### DNS 是否正确

```bash
nslookup api.jiatuc.cn
```

### 腾讯云防火墙是否开放

确认轻量服务器防火墙入站有：

```text
80
443
```

### Caddy 是否拿到证书

```bash
cd /opt/new-api
sudo docker compose logs --tail=100 caddy
```

如果出现 timeout，通常是公网 `80/443` 没通。

### New API 是否正常

```bash
curl -i http://127.0.0.1:3000/api/status
```

如果本机正常、公网不正常，优先查防火墙、备案、Caddy。

## 10. 后续维护

查看状态：

```bash
cd /opt/new-api
sudo docker compose ps
```

查看日志：

```bash
sudo docker compose logs --tail=100 new-api
```

更新：

```bash
cd /opt/new-api
sudo docker compose pull
sudo docker compose up -d
```

备份 PostgreSQL：

```bash
cd /opt/new-api
sudo mkdir -p backups
sudo docker compose exec -T postgres pg_dump -U newapi -d new-api > backups/new-api-$(date +%F-%H%M%S).sql
```
